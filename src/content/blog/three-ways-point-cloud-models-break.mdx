Every point-cloud segmentation model I have trained has looked excellent on the validation split
and then done something embarrassing on the first real survey it saw. The gap is rarely the
architecture. It is almost always that the benchmark quietly guaranteed something the real world
does not.

Here are the three failure modes I keep running into, and what actually fixed them.

## 1. Density shift between training and inference

Benchmarks are usually captured with one sensor at one altitude. Production data is not. The same
tower scanned from a drone at 30 m and from a terrestrial scanner produces wildly different local
point densities, and a model that learned "this many neighbours within 30 cm means tower body"
falls apart when that number halves.

The fix that worked was normalising density before the model ever sees the points — Poisson-disk
downsampling to a fixed radius, so every input has roughly the same spacing regardless of how it
was captured.

```python title="preprocess/normalize_density.py" showLineNumbers
import numpy as np
from scipy.spatial import cKDTree


def poisson_disk_subsample(xyz: np.ndarray, radius: float) -> np.ndarray:
    """Greedy Poisson-disk thinning: no two kept points closer than `radius`."""
    tree = cKDTree(xyz)
    order = np.random.permutation(len(xyz))
    keep = np.ones(len(xyz), dtype=bool)

    for idx in order:
        if not keep[idx]:
            continue
        # Suppress every neighbour inside the disk except the point itself.
        for neighbour in tree.query_ball_point(xyz[idx], radius):
            if neighbour != idx:
                keep[neighbour] = False

    return np.flatnonzero(keep)
```

The important detail is that this runs at *both* training and inference time. Normalising only one
side of the pipeline moves the distribution shift around rather than removing it.

## 2. Class imbalance that the loss quietly ignores

On a typical infrastructure scan, `Noise` and `Tower Body` account for the overwhelming majority
of points, while the classes you actually care about — panel antennas, microwave dishes, RRUs —
might be under 2% combined. Cross-entropy will happily reach 97% accuracy by never predicting the
small classes at all.

Log-scaled class weights help more than the usual inverse-frequency weighting, which tends to
overcorrect and produce a model that hallucinates rare classes everywhere:

```python title="train/losses.py"
import torch
import torch.nn.functional as F


def log_scaled_weights(counts: torch.Tensor, eps: float = 1.02) -> torch.Tensor:
    """Softer than 1/freq — compresses the dynamic range of the weights."""
    freq = counts / counts.sum()
    weights = 1.0 / torch.log(eps + freq)
    return weights / weights.mean()


def loss_fn(logits, target, counts):
    return F.cross_entropy(logits, target, weight=log_scaled_weights(counts))
```

Watch per-class IoU rather than mIoU while tuning this. A mean can hide a class sitting at zero,
and the mean is exactly the number that looks fine in your training logs.

## 3. Geometry that only exists at one scale

A flat surface at a 30 cm neighbourhood radius can be a curved surface at 1 m. Models given
single-scale geometric features tend to confuse thin cylindrical structures with flat panels,
because at the scale they were shown those two things genuinely look identical.

Computing planarity and scattering at two neighbourhood sizes — and feeding the *difference*
between them as its own feature — gave the single biggest jump in rare-class IoU of anything on
this list. The difference is what encodes "this looks flat up close but curved further out".

> The general lesson: if a human needs to zoom in and out to tell two classes apart, a
> single-scale feature vector is not going to manage it either.

## What I would check first

If a point-cloud model is underperforming in production and you only have time for one
investigation, compare the point-density histogram of your training set against a real production
tile. In my experience that single plot explains more failures than any of the architecture
choices people usually reach for first.
